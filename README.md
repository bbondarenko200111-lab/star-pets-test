# Тестовое задание StarPets

## 1. Слабые места в требованиях

**Что не учтено:**

- **Внутренний баланс и race condition** – два быстрых клика могут списать деньги дважды. Нет механизма блокировки (`SELECT FOR UPDATE` или per‑user очередь).
- **Отсутствие холда** – деньги списываются до выдачи предмета. При сбое CV деньги потеряны. Нужно резервирование → подтверждение/откат.
- **Computer Vision как единственный источник истины** – CV ошибается (освещение, скины). Нет ретраев и DLQ. Нужен fallback (ручная проверка).
- **Асинхронная цепочка без компенсаций** – нет state-машины (PENDING → PAID → DELIVERED/FAILED). При фейле CV нет отката.
- **Привязка Roblox‑аккаунта** – не сказано, как убедиться, что в игре тот же пользователь. Риск подмены.
- **Комиссия** – не ясно, когда и как применяется, показывать ли до клика.

## 2. Работа с закрытым бэкендом (Black‑Box / Grey‑Box)

### Black‑Box (видим только фронтенд)
- Локаторы `[data-testid="..."]` – не ломаются при смене дизайна.
- Асинхронные ожидания – только встроенные в Playwright (`waitFor`, `toBeVisible`), никаких `sleep`.
- Не проверяем состояние очередей, БД, логов бота.

### Grey‑Box (используем частичные знания)
- Слушаем WebSocket (если открыт) через `page.waitForEvent('websocket')`.
- Мокаем API‑ответы через `page.route()` (для эмуляции задержек).
- Через API сайта проверяем статус заказа (long polling).

**В нашем тесте:** Проверяем, что после клика «Купить» появляется кнопка «Вывести». Это косвенно подтверждает, что WebSocket обработал событие. Всё остальное (очередь, бот, CV) – зона интеграционных тестов, не UI.

## 3. Автотест: архитектура, стиль, стабильность

**Структура проекта (минимальная, но достаточная):**
star-pets-test/
├── pages/
│ └── shopPage.ts # Page Object
├── fixtures/
│ └── testData.ts # тестовые данные
├── tests/
│ └── purchase.spec.ts # единственный UI-тест
├── playwright.config.ts
├── package.json
├── tsconfig.json
└── README.md

**Ключевые решения:**
- **Локаторы** – только `data-testid`.
- **Ожидания** – без хардкода, Playwright ждёт автоматически.
- **Page Object** – скрывает селекторы и действия.
- **Фикстуры** – выносят тестовые данные.
- **Один компактный тест** – не перегружен, проверяет только появление кнопки после WebSocket.

**Почему тест стабилен:**
- Не зависит от внешних платежей (используется внутренний баланс).
- При отсутствии бэкенда падает с понятным таймаутом.
- Легко адаптируется под разные окружения через `baseURL` в конфиге.

## 4. Запуск тестов (локально)

1. Установите [Node.js](https://nodejs.org) (LTS).
2. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/bbondarenko200111-lab/star-pets-test.git
   cd star-pets-test
   Установите зависимости:
   npm install
   npx playwright install
   Запустите dev‑сервер Nuxt приложения (обычно npm run dev на http://localhost:3000).

Выполните тест:
npx playwright test
Тест откроет карточку товара → проверит цену → нажмёт «Купить» → дождётся появления кнопки «Вывести» (максимум 15 секунд).
Если кнопка не появилась – тест упадёт с таймаутом, что говорит о проблеме в цепочке WebSocket → бот.
