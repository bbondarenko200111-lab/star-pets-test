# StarPets Test Assignment – QA Engineer

## Решение

### Блок 1. Продуктовое мышление (текст в начале README)

#### 1. Критика требований и вопросы к PM
- **Race condition** при быстрых кликах – нет блокировки баланса.
- **Отсутствие холда** – деньги списываются до подтверждения выдачи.
- **Computer Vision** – ненадёжен, нет fallback-сценариев.
- **Асинхронная цепочка** – нет state-машины и компенсаций при ошибках.
- **Привязка Roblox** – нет проверки, что тот же пользователь в игре.
- **Комиссия** – неясно, когда и как показывать.

Вопросы на груминг:
- Какая гарантия доставки RabbitMQ? Есть ли идемпотентность?
- Как восстанавливаемся после падения CV?
- Можно ли получить API для проверки выдачи?

#### 2. Edge Cases
- Двойной клик – проверка на идемпотентность.
- Нехватка баланса – корректная ошибка, откат.
- Вебхук от платёжки не пришёл – таймауты, повторные попытки.
- Ошибка Roblox-бота – повтор, логирование, ручной fallback.
- CV не распознал предмет – повтор, уведомление пользователя.

#### 3. Пострелизный мониторинг
- Метрики: % успешных транзакций, P95 задержки WebSocket, количество ошибок в очереди.
- Инструменты: Grafana + Prometheus, ELK, Sentry, алерты в Slack.
- Проверять: нет ли резкого роста времени ответа, не падает ли успешность ниже 95%.

#### Запуск локально
```bash
npm install
npx playwright install
# Запустить dev-сервер приложения (если есть)
npm run test          # все тесты
npm run test:ui       # только UI
npm run test:api      # только API
npm run test:headed   # с открытым браузером
npm run report        # открыть HTML-отчёт
Особенности реализации
Локаторы – только data-testid для устойчивости.

Ожидания – только встроенные механизмы Playwright, без sleep.

Page Object – инкапсулирует селекторы и действия.

API-тесты – покрывают контракт, негатив, 401, идемпотентность (с пояснениями).

Разделение – UI и API в отдельных проектах Playwright.

Все тесты работают на публичных API. Для эмуляции 401 используется httpbin.org, для негативных сценариев – reqres.in. UI-тест проверяет реальное поведение приложения (ожидается, что бэкенд отдаёт WebSocket-событие). Тест идемпотентности помечен как skip и содержит подробные комментарии, так как jsonplaceholder не поддерживает эту функциональность.
